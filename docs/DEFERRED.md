# Deferred

Issues and features we chose not to do yet: when, why not now, and what would bring each back.
When one is picked up, move it out of this file and into the plan or the change that does it.

| Date | Item | Why not now | Revisit when |
|---|---|---|---|
| 2026-10-22 | Virtualized or paged editing for very long pages | A keystroke on a 2000-paragraph page takes 8–11 ms (the first about 13 ms), inside a 16 ms frame. Rendering part of a page needs a new editor architecture and tends to break browser find, cross-block selection and copy. | Someone finds typing slow. To check: fill a page with 2000 paragraphs (`__editor.commands.setContent`), type 30 keys, time each from keydown to its transaction; the budget is 16 ms. |
| 2026-10-22 | ⌘D and ⌫ while the block menu is open | The open menu holds focus, so the shortcuts it shows only work once it closes. Small, and nobody has asked. | Someone presses a shortcut with the menu open and expects it to run. |
| 2026-10-22 | Block menu items Notion has beyond Turn into, Duplicate and Delete: colours and highlights, copy link to block, move to another page, comments | Colours need a new block attribute and a palette that reads in light and dark. Links, moves and comments need block ids and links between pages. | Colours when asked; the rest with M2. |
| 2026-10-22 | Math blocks | Left out of the block set on request. | When asked. |
| 2026-10-22 | Queries: saved, rule-based lists of pages | Left out of M2 on request. Lists of a type, a tag, a relation or backlinks, with sort and group, cover most uses. | A list someone needs can't be built without a saved rule. |
| 2026-10-22 | Block references (`((`) and tags on single blocks | Every block needs a lasting id, and editing one block in several pages at once is the hardest part of ProseMirror. | After M2's links and backlinks ship. |
| 2026-10-22 | Images, web links, PDFs and audio as pages | They fit the page model as pages whose main property is the file or link, but each needs its own preview, fetch or reader work. | After M2. |
| 2026-10-22 | Graph view | Needs the links table first, and shows little until there are many links. | After M2, when asked. |
| 2026-10-22 | Side-by-side pages kept after a reload or restart | Asked for the simplest form; a reload opens one page, as before. | Someone misses their layout after a restart. |
| 2026-10-22 | The Ask panel with panes side by side | It docks to the page area's corner, so it can sit over the other pane, and it doesn't name the page it's about. Its top corners can cover a pane's close button and the cover's credit; at the largest text size it overlaps the cover's buttons by 6 px; opening a page beside it closes it, since Ask follows the page last opened. The panel is still being built on main, so placing it per pane is left to that work. | The next pass on Ask or the agents area. |
| 2026-10-22 | Browser windows 768–799 px wide | The sidebar turns into a sheet below 800 px but the page area's margins switch at 768 px, so in that band the cards sit oddly. The Mac window can't be narrower than 800 px. | Someone uses the browser build at that width. |
| 2026-10-22 | Tab order of pages side by side | Cards keep the order they were opened in, so a moved page isn't mounted again and keeps its edits; Tab follows that order, not left to right. | Keyboard moving between pages, or a screen reader user. |
| 2026-10-22 | The selection toolbar after its card moves | With pages side by side, a toolbar shown for a selection can stay where it was when the card is moved or resized, or sit clipped at the card's edge, until the selection changes. It came with panes. | Someone notices it in daily use. |
| 2026-10-22 | A minimum pane width | A split stops at 10% of its space, so panes can get narrower than any view: a tag page's list clips below about 200 px, the cover's buttons sit over the page icon below about 340 px, and the selection toolbar (262 px) and the ask bar can't fit in cards narrower than they are. A real minimum needs limits across nested splits, new splits and window resizes. | Someone works with three or more panes in a small window. |
| 2026-10-22 | Splitting, moving or resizing panes from the keyboard or a menu, and dropping on a page's middle | Dragging covers the ask; Shipyard's swap-on-middle and split commands were left out, and dividers can't take focus. | When asked, or with the command palette. |
| 2026-10-22 | Editing a page where it is embedded | An embed is read-only: two editors on one page need shared editing state, as below. Its title opens the page itself. | With one page open in two places. |
| 2026-10-22 | One page open in two places at once | Two editors on one page need shared editing state. Capacities doesn't allow it either. | When asked. |
| 2026-10-22 | Stickers as page icons and in pages | Waiting to hear what "stickers" should be; a free set like Microsoft's 3D emoji is the guess. | When that's settled. |
| 2026-10-22 | Emoji skin tones | Not asked for; every emoji shows in its default tone. | When asked. |
| 2026-10-22 | Editing values inside lists, and dragging cards between board columns | Lists show values; changing one opens the page. Editing in cells means a second editor for every kind. | Someone fills in many pages of a type at once. |
| 2026-10-22 | Starting a page from a template with a slash command | "New" with its template menu covers it; the slash menu would need to create and link in one step. | When asked. |
| 2026-10-22 | Editing a two-way relation from the other side | The other side shows the linked pages read only; adding one there would write to another page. | When asked. |
| 2026-10-22 | Deleting a property everywhere | Removing it from a page or a type covers tidying up, and its values stay stored either way. | Someone wants unused properties gone from the "Add property" list. |
| 2026-10-22 | Mermaid diagrams in code blocks | A large extra dependency for a niche use. | When asked. |
| 2026-10-22 | Highlight blocks from reading integrations | There are no integrations to bring highlights in. | When an integration is built. |
| 2026-10-22 | Width options for columns and groups | Equal widths cover the common case. | When asked. |
| 2026-10-22 | Drag-to-resize sidebar | sidebar-08 has a fixed 256 px sidebar; dropped when we moved to it. | When asked. |
| 2026-10-22 | The agent panel's threads live only while the app runs, and it docks to corners rather than being dragged freely | A first working version; the designer's pass (the brief, Task D) sets the real shape. | With the designer's panel. |
| 2026-10-22 | Small panel points from QA: Escape doesn't close it while the editor has focus (the editor owns Escape there); the corner menu pokes 2 px past the page panel; the toolbar's tooltip covers text; near the top of a page the selection toolbar flips below the words | Each is a few pixels or a focus rule, best taken with the designer's panel. | With the designer's panel. |
| 2026-10-22 | A "Sign in" button that runs `claude auth login` for you, and a keepalive so the Keychain token (about 8 h) never lapses mid-session | The panel and Settings › AI say what to run in Terminal instead; synara's keepalive runs `claude auth status` every 30 min. | If "not signed in" shows up after long sessions. |
| 2026-10-22 | GPT through Codex as a second provider | One `ask` interface exists; Codex would speak `codex exec --json` through the same Rust shape. | When asked. |
| 2026-10-22 | A General section of our own (where notes are stored, show the folder) | Shipyard's General is all agent and terminal rows, so Settings opens on Appearance for now. | With the designer's Settings pass (the brief). |
| 2026-10-22 | Shipyard's wording in the Shortcuts and About sections ("terminals included", "docs.berthd.app", "berthd on devl") | Those two are still Shipyard's components; Appearance is ours now. | With the designer's Settings pass (the brief). |
| 2026-10-22 | Shipyard's `check-grid`, `check-type` and `check-titles` only check the vendored tree | The scripts resolve `../src` from their own folder; pointing them at `apps/desktop/src` needs a root argument upstream or a wrapper of ours. | When our own classes move onto the type scale and grid. |
| 2026-10-22 | Two copies of the COSS components (vendor `components/ui` and `packages/ui`) and two toast providers | Same tokens, same look; aliasing one onto the other risks Shipyard's own edits (its sidebar, tooltip). | When the new UX settles which set each screen uses. |
| 2026-10-22 | A cold dev load through the Berth browser proxy takes 20–46 s (250+ module requests); Vite's hot-reload socket fails through it | Settings now loads lazily, which cuts most of the modules; the socket is the proxy answering the upgrade with a 200, not the app. Headless Chromium against Vite loads in about a second. | If the Berth browser stays slow after the lazy load; the socket is a Berth question. |
| 2026-10-22 | White text on a theme's destructive colour is under 4.5:1 in several dark themes (Tokyo Night 2.65:1, Midnight 2.75:1): the Delete button | COSS's destructive button paints white on `--destructive`; Shipyard's contrast check doesn't cover that pair, and its themes weren't tuned for it. | When themes get a check of their own for the buttons we draw, or the button takes `--destructive-foreground`. |
| 2026-10-22 | Nord: the sidebar and the page are the same colour, so the inset panel's edge vanishes; Solarized Light: the selected sidebar row barely shows; Tokyo Night: menus nearly match the page | sidebar-08 relies on sidebar and page differing; Shipyard's own shell doesn't. A hairline on the panel and a stronger selected row would fix the first two for every theme. | When the shell gets its pixel pass under themes. |
| 2026-10-22 | Text size changes the sidebar's width (256 px only at the default) but not the editor's title and body, which are in px | Shipyard sizes everything in rem on purpose; the editor's scale was set in px before themes arrived. | When the editor's sizes move to rem, so Text size means the page too. |
| 2026-10-22 | Vendored code that calls Shipyard's Rust commands (Developer section, the CLI link in General, the updater) fails in the Mac app | `isTauri()` is true there but the commands don't exist; mock mode keeps the agent data off that path. | When the native side is wired, or those sections are trimmed. |
| 2026-10-22 | The conversation UI and agent plumbing are vendored and build, but nothing mounts them yet; the plugin system is source only | They run on mock fixtures only; the agents area is the new UX to design. | When the agents area starts. |
| 2026-10-22 | Chromium drops a media block's selection when it sits between two media blocks | The Mac app (WebKit) keeps it. Chromium has no caret spot between two non-editable blocks, so on page refocus it moves the caret to the page start. Only DevTools-driven input (the QA harness) triggers it reliably. A fix exists (about 30 lines plus a test, commit `dd03cda` on branch `worktree-agent-a9523810594569085`, not merged), but it rests on a timing guess. | We ship a Chromium-based build, such as Windows, where Tauri uses WebView2. |
| 2026-10-22 | Own handles for list items inside columns | A handle beside an item in column 2 would sit over column 1's text; hovering by height alone also picked the wrong column (QA R10-1). The columns block keeps one handle. | Column gaps wide enough for a handle, and column-aware hovering. |
| 2026-10-22 | Mentions as chips in a row above the composer's field, not inline in the text as synara's Lexical editor does | Inline chips need a rich-text field (synara uses Lexical); a plain textarea with a chip row gives the same mentions for a tenth of the code. | If mentions in the middle of a sentence are missed, or the panel gets a rich field for other reasons. |
| 2026-10-22 | An agent's `tools`, `skills` and `permissionMode` front matter, and synara's voice input, image attachments and slash-command file (`.claude/commands`) | Agents here are prompt presets with a model; the subprocess runs with `--tools ""`, so tools would need a permission story first. Commands are a fixed list of seven. | When an agent needs to read files or search, or someone writes their own commands. |
| 2026-10-22 | The ask bar's field is one line, with no @ or / | Shipyard's bar is one line too; the composer in the panel has the menus. | If people ask long questions from the bar. |
| 2026-10-22 | A file card that shows its file is missing | Images, video and audio learn this for free from a failed load; a file card would need a disk check per card. In the app, clicking a card whose file was moved or deleted does nothing. | Someone hits a dead file card. |
| 2026-10-22 | A checked to-do keeps the exact pen marks it was checked with | Each check draws a new random wobble. A reload or a moved block redraws from a seed built from the text, so the marks change shape slightly. Keeping them means storing a seed in every to-do. | Someone notices the marks change. |
| 2026-10-22 | Sidenotes on blocks without text (image, video, file, embed, code, divider) | A note's anchor is a mark on words, and these blocks hold none (code allows no marks). Needs an anchor attribute on each block kind and a chip placed on the block. | Someone wants to note an image or a code sample. |
| 2026-10-22 | Sidenotes inside an essay or a Thoughts page | Each would need its own Thoughts page, two levels under the source, and the sidebar tree is one level deep. | Writing essays shows a need to annotate them. |
| 2026-10-22 | Quotes into an essay from a sidenote or the Thoughts page | "Add to essay" works on the source page's own text, which is the case asked for. | Essay writing shows notes being quoted often. |
| 2026-10-22 | References in an essay follow a renamed or deleted source | A reference keeps the source's title from when it was quoted, and one whose source was deleted does nothing on click. Live titles need the editor to look titles up from the app. | Renames or deletes of quoted pages turn out to be common. |
| 2026-10-22 | The drop preview while panes are folded | Folding (a page with sidenotes and no room) lays panes out differently from their split, and the drop preview still draws the split. The drop itself lands right. | Folding is used often with dragging. |
